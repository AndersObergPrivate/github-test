# Contributing to the DevRel Roadmap

Thank you for contributing to our Developer Relations roadmap! This document provides guidelines for how to contribute effectively.

## 📋 How to Contribute

### Adding a New Initiative

1. **Create the initiative document**
   - Copy `roadmap/templates/initiative-template.md`
   - Save it as `roadmap/initiatives/[initiative-name].md`
   - Use lowercase and hyphens for the filename (e.g., `developer-documentation-refresh.md`)

2. **Fill in all required sections**
   - Provide clear goals and success metrics
   - Identify owners and stakeholders
   - Create a realistic timeline
   - Document budget requirements if applicable

3. **Create a tracking issue**
   - Open a new GitHub issue
   - Link it to your initiative document
   - Add appropriate labels (e.g., `initiative`, `Q1-2024`)
   - Assign it to the initiative owner

4. **Submit a pull request**
   - Create a PR with your new initiative
   - Request review from relevant stakeholders
   - Include a summary of the initiative in the PR description

### Updating an Existing Initiative

1. **Make your changes**
   - Update the relevant sections in the initiative document
   - Add notes in the "Notes & Updates" section with date

2. **Submit a pull request**
   - Clearly describe what changed and why
   - Tag the initiative owner for review

### Quarterly Planning

1. **Create quarterly roadmap**
   - Use `roadmap/templates/quarterly-template.md`
   - Save as `roadmap/quarters/YYYY-QX.md` (e.g., `2024-Q1.md`)
   - Fill in all initiatives planned for the quarter

2. **Review process**
   - Share with the entire DevRel team
   - Incorporate feedback
   - Get approval from DevRel leadership

## ✅ Best Practices

### Writing Clear Objectives

- Use specific, measurable goals
- Avoid vague language
- Include concrete success metrics
- Set realistic timelines

### Updating Status

- Update initiative status regularly (at least bi-weekly)
- Keep metrics current
- Document blockers and risks promptly
- Celebrate wins in the updates section

### Collaboration

- Tag relevant stakeholders in PRs and issues
- Use GitHub Projects to track progress
- Keep communication transparent
- Share learnings and insights

## 🏷️ Labels & Tags

Use these labels on GitHub issues:

- `initiative` - A major DevRel initiative
- `quarterly-planning` - Related to quarterly planning
- `content` - Content-related initiatives
- `community` - Community engagement initiatives
- `developer-experience` - DX improvements
- `partnership` - External partnerships
- `Q1-YYYY`, `Q2-YYYY`, etc. - Quarterly tags

## 📞 Getting Help

If you have questions:
- Post in the DevRel team channel
- Tag `@devrel-team` in issues or PRs
- Reach out to your DevRel lead

## 📝 Review Process

1. **Peer Review**: At least one team member should review
2. **Stakeholder Review**: Relevant stakeholders should approve
3. **Leadership Approval**: Major initiatives need leadership sign-off

## 🔄 Maintenance

- Archive completed initiatives to `roadmap/archive/` at quarter end
- Review and update templates as processes evolve
- Keep the main README up to date
